# QQ 导出与事件分析

将 QQ 群聊转成可执行的事件摘要；不逐条复述闲聊。

- 若用户已提供 JSON 文件或明确其路径，直接读取并分析，不调用导出接口；该路径不需要 QCE，也不受平台限制。
- 若用户要分析但尚无 JSON，先确认待分析的群号或唯一群名；信息不足时只询问这一项。
- 需要本机 QCE 时先跑 `scripts/qce_env.py check` 体检；缺依赖就说明缺什么并获得用户同意后再 `install`（从上游官方 Release 下载并校验 sha256），绝不猜测安装路径、不代替用户安装软件。
- 已确定群聊后，先用 `scripts/qce_automation.py resolve-group --name` 验证唯一群名或直接使用群号，再以 `export --format JSON --wait` 导出；读取前核验完成任务的 `filePath` 是可读 JSON。
- QCE 是本机 HTTP 服务，默认地址为 `http://127.0.0.1:40653`，不需要浏览器；Windows Shell 包用 `scripts/qce_qr_login.py` 隐藏启动器并弹出扫码窗口，省略 `--qce-root` 时脚本会自己定位目录；NapCat 已在本机运行时加 `--no-launch`，避免重启 QQ。二维码过期时脚本会调用 `RefreshQRcode` 自动换新码；连续失败或等待扫码超过 `--scan-timeout`（默认 300 秒，0 表示不超时）时说明原因并自动关窗，不留无人值守的窗口。
- 登录过程写入 `--log-file`，默认依次尝试 QCE 的 `logs/qce-qr-login.log`、`~/.qq-chat-exporter/logs/` 与系统临时目录，均不可写则静默降级；日志只记录状态与错误，绝不记录令牌或二维码内容。登录报错先读日志核对原因，不必让用户重述窗口里一闪而过的提示；扫码后等待 QCE 就绪，不代替用户登录或保存凭证。
- 导出脚本依次使用 `QCE_TOKEN`、临时 `--token`、本机 QCE 配置 `~/.qq-chat-exporter/security.json` 的 `accessToken`，最后才要求终端不回显输入；令牌只用于本机请求，绝不写入脚本、报告或聊天回复。
- QCE 无法连接、鉴权失败、导出失败或超时时原样说明错误；仅在用户明确要求时创建、触发或查看定时导出。
- 导出的原始 JSON 是聊天源数据；最终报告默认保存为 `reports/qq-chat/{群号}_{安全群名}/{分析时间}_事件分析.md`，群名中的非法文件字符替换为 `-`，不覆盖历史报告；用户指定路径时优先遵从。
- 创建报告后仅回复其本地链接与一句完成说明，不重复粘贴完整报告；不删除源 JSON。

## 事件判断

- 解析 `chatInfo`、`statistics`、`messages`、`sender.name` 与 `content.text`；回复消息结合 `content.elements` 的被回复内容。
- 合并同一现实事项的多条消息，记录提出、确认、更新或负责者；以明确确认和最新进展为准；同名群聊时要求用户按群号选择。
- 不臆测图片、附件或模糊话语；未读出的内容写“图片内容未识别”，并排除问候、闲聊和无后续推荐。

## 日期与输出

- 开头说明群名、消息时间范围、消息数与分析时区；默认将时间戳按 UTC 转为 UTC+8，除非用户指定其他时区。
- “截至日期/时间”只填聊天中明确说出的截止时间；发送时间只作证据，绝不能替代截止时间；未提及写“未提及”。
- 保留“国庆前”等相对时间原话，不虚构精确日期；未确认的时间、结论或行动移至最后的“待确定事项”。
- 分为“已明确事项”和“待确定事项”两块，各自使用表格：`截至日期/时间 | 事件 | 谁提到/跟进 | 结论与当前状态`。
